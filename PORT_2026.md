- **Engine:** 26.11.10a (`horrorjam.sbproj`, project `apetavern.gvar_jam`)
- **Source of truth:** `2023-repo/` (GvarJam, `.NET 6/7`, `GameManager` + `Entity` API, last commit `48fce9b`)
- **Target:** modern scene/component API (`Component`, `GameObject`, `Scene`, `MapInstance`, Razor `PanelComponent`, `SoundHandle`, `NavMeshAgent`, `CharacterController`), keeping AG1 `.vanmgrph` initially
- **Branch:** `2026-rework` (`master` untouched; uncommitted working tree ready for user playthrough/commit)
- **Current status:** **Port executed, compiled (`0` errors), publishing rules configured (`350` files / `116.70 MB` / `0` code warnings), and subsystem-verified in Play Mode.** Pending: one final human end-to-end playthrough from Cryo → Credits.

## Port Execution Summary — What It Actually Took

1. **Custom `MapInstance` loader over cloud `apetavern.horror_jam_map` (`Code/Map/ColdOpenMapInstance.cs`):**
   - Instead of re-porting the raw `.vmap`, loaded the compiled cloud map `apetavern.horror_jam_map` inside `Assets/scenes/minimal.scene` via `ColdOpenMapInstance : MapInstance`.
   - Overrode `OnCreateObject(GameObject, MapLoader.ObjectEntry)` to swap all 62 unimplemented map entities (`ent_door_custom` ×15, `ent_storagelocker` ×9, `ent_playerlocker` ×7, `ent_item` ×5, `ent_mountedcamera` ×5, `ObjectiveTrigger` ×4, `ent_cameracontroller` ×3, `ent_note` ×2, `info_target` ×5, `ent_helmet`, `ent_generator`, `ent_console`, `ent_splitizen`), preserving prefab-prefixed `TargetName`s (`523_note_danger`, `1374_final_door`, `523_wakeup_intro_trigger`), tagging doors `"door"` for NavMesh exclusion, removing leftover `MapObjectComponent` static proxies on replaced objects, dressing `nosplit_blank` corpses with `blue_jumpsuit.clothing`, and baking runtime NavMesh on map load.
2. **Broken 2023 `.vmdl` `import_filter` repair (40 models):**
   - Old ModelDoc matched `import_filter.exception_list` against FBX **Geometry** names (`box_low_001`, `Keycard_005`, `Cube_005`, …), whereas modern ModelDoc matches FBX **Model** node names (`Box_low`, `Keycard_low`, `Locker_low`). That left **38 props completely blank** (`verts=0`) and **2 lockers (`locker`, `slimplayerlocker`) missing their bodies**. Switched all 40 to `exclude_by_default = false`, enabled `use_global_default = true` on `keycard.vmdl` & `slimplayerlocker.vmdl`, and verified **97/97** models compile with real geometry.
3. **`cryarmsv2.vmdl` editor freeze & cutscene fallback:**
   - `cryarmsv2.vmdl` froze Asset Browser previews and Play Mode because its `RenderMeshFile` (`CryoArmAnimationsV2.fbx` with `Cube` stripped) compiled to **`bones=1`** (missing `Head` for `camPos`) alongside `cryarmsv2.vanmgrph`. Fixed by pointing its `RenderMeshFile` to `CryoArmRig.fbx` (`bones=43`, `camPos` valid) and clearing `anim_graph_name = ""`.
   - Replaced `citizen_skin04.vmat` → `models/citizen/skin/citizen_skin.vmat` on `cryarmsv2`, `escapepodarms`, and `selfdestructarms`.
   - Added `SkinnedModelRenderer.Sequence` playback in `CutsceneRunnerComponent` (`waiting` while awaiting Jump → `Hitbutton` @ 1.5x → `Fallout` @ 1.75x, plus `HitKeyboard` and `EscapePodComplete` @ 1.0x for `Sequence`-only cutscenes).
4. **Shader & Camera Console `RenderTarget` (`lcd_shader.shader` + `CameraControllerComponent`):**
   - Ported `Assets/shaders/lcd_shader.shader` to 2026 VFX (`Forward()`, `Depth(S_MODE_DEPTH)`, `MainVs(VertexInput)`, `Material.CommonInputs.hlsl`, `WRAP` sampler, manual Schlick Fresnel), compiling 10 combos and unblocking `monitor.vmat`, `monitoroff.vmat`, and `console_screen.vmdl`.
   - Replaced removed `ScenePortal` with `CameraComponent.RenderTarget` (`512x512` `RGBA8888`) bound to a dynamic copy of `monitor.vmat` via **`g_tColor`** (not `"TextureColor"`, which is only a `.vmat` compile-time input and left the screen white).
5. **Objectives KV3 → JSON + trigger detection + `final_door`:**
   - Converted all 10 `.objctv` files from KV3 to `ObjectiveResource` JSON (`[AssetType]`) and persisted them onto `ColdOpenMapInstance.Objectives` in `minimal.scene` so `PublishUsedAssetsOnly` includes and preloads all 10.
   - `CharacterController` has no physics `Collider`, so `ModelCollider.OnTriggerEnter` never fired; added `BBox.Overlaps` checks in `ObjectiveTriggerComponent.IsTouching(player)`.
   - Added `BypassItemRequirement` in `DoorControllerComponent` unlocked by `SetDoorLockState(DoorLocked: false)` so `final_door` (which defaulted to `JanitorKey`) always opens when the Escape objective starts.
6. **Player, Flashlight, Lockers, Respawn & `ZNear`:**
   - Fixed `CutsceneRunnerComponent.EndCutscene()` clearing `HidingPlayers = false` (restoring 3rd-person/interaction player visibility) and moved `_player` resolution to `OnAwake()`.
   - Fixed `HelmetLampComponent` aim by parenting `HelmetSpotLight` to the player root instead of the animated bone-merged `"light"` attachment (`SyncLampTransform()` in `OnPreRender()` matches `EyeRotation` cleanly with zero parallax in 1st person) and stopped `OnFixedUpdate` from overwriting `Tint.a`.
   - Fixed `PlayerLockerComponent` camera (removed `cameraRot.Inverse` and placed peek camera outside the `X = 46.6` locker door bounds at `Forward * 54f`, `Up * 64f` with `±75°` yaw / `-25°..35°` pitch look, `IsHidingInLocker` body hiding, and monster stealth).
   - Set `ActiveCamera.ZNear` dynamically (`10f` in cutscenes, `4f` in gameplay).
   - Added `ColdOpenGame.RegisterBatterySpawn` / `RespawnWorldBatteries` + full helmet battery/stamina reset and `Hunting` → `Stalking` monster reset on `ColdOpenPlayer.Respawn()`.
7. **Splitizen & Monster AI (`NavMeshAgent` + `CharacterController` + AG1):**
   - Restored `BoneMergeTarget = _bodyRenderer` on `_cosmeticMonster`, `_splitTopRenderer`, and `_monster` (until `"decouple"`): they share only `pelvis`, keeping the dormant monster tucked inside the torso and letting `basic_splitizen.vanmgrph` drive `bangdoor`/`split`.
   - Added `CharacterController` (`_agent.UpdatePosition = false` + `SetAgentPosition`) so Splitizen & Monster physically stop at closed doors (`bangdoor = true`) instead of phasing through them.
   - Fixed Monster state assignment order (`_state = value` before `OnStateChange`), throttled `SetPath` calls, smoothed `walkspeed` with a `0.15` floor while navigating (stopping idle/walk animation chatter), and added `HasLineOfSight(player)` (since `ColdOpenPlayer` has no `Collider`) so `LampEnabled == true` reliably sends the monster into `Hiding`.
8. **UI & Publishing (`horrorjam.sbproj`):**

## 0. Verdict

The port is **viable 1:1**. The game is small in code (~7.5k lines, 75 files) and almost all of it is game logic that maps cleanly onto components. The expensive parts are not code:

| Area | Difficulty | Why |
|---|---|---|
| Map | **Low** | Old `vmap 29` **opens in current Hammer** — verified. 12 prefab instances + 3 root entities preserved; prefab instancing already exists |
| Game logic | **Medium** | Mechanical rewrite: `Entity`→`GameObject`, `[Net]`→`[Sync]`, `[ClientRpc]`→`[Rpc.Broadcast]`, `Event.Tick`→`OnUpdate/OnFixedUpdate`, `HudEntity`→`PanelComponent` |
| Assets | **Medium-High** | 97 `.vmdl` + 89 `.vmat` are 2023-format. Materials compile-guard whole model trees; old shader is dead. Needs a re-save/repair pass |
| Interaction/animation polish | **Low-Medium** | Old game leaned on `CitizenAnimationHelper`, anim parameters (`grabitem`, `puthelmet`, `split`, `bangdoor`), first-person IK and per-bone props. **AG1 (`.vanmgrph`) still works** in the current engine, and `CitizenAnimationHelper` still targets AG1 — keep existing graphs to get running, deferring AG2 (`.ag`) migration |
| Camera console (ScenePortal) | **Medium** | `ScenePortal` no longer exists; use `CameraComponent.RenderTarget` → material/`WorldPanel` |

Two functional regressions must be designed around, not hand-waved:

1. **Name-based objective targeting breaks under prefab instancing.** Instanced doors are renamed `523_8_Door_00`, `532_13_Door_00`, … (verified in the map). The old code matched entities by `Name.Contains(...)`. Objective `DoorName = "final_door"` works only because that door lives directly in `room_escape_01a`.
2. **`ObjectiveResource` is KV3 (`.objctv`) with `resource:` typed refs.** Modern `GameResource` is JSON. 10 resources need a one-time conversion (mechanical; formats below).

## 2. The game, as designed

### 2.1 Story / objective chain (from `data/objectives/*.objctv`)

Objectives are *data-driven*: each resource has start conditions, end conditions and events. The chain below is the whole game.

| # | Resource | Objective | Start condition | End condition | Events on start / end |
|---|---|---|---|---|---|
| 1 | `wakeup` | Wake Up | player enters `wakeup_intro_trigger` | *(none)* | start: instantiate `cryarmsv2.vmdl` at `cryo_sleep_pos`, attachment `camPos`, extra `cryochamber.vmdl`, **input required**, 9.3 s, hide players |
| 2 | `findjanitorkey` | Locked In | `wakeup` complete | `PlayerHasItem KeycardLvl1` | — |
| 3 | `locatehelmet` | Locate Helmet | `findjanitorkey` complete | `InteractedWithType Helmet` | — |
| 4 | `findbatteries` | Batteries Not Included | `locatehelmet` complete | `InteractWithType LampBattery` | — |
| 5 | `leaveroom` | Leave the Room | `findbatteries` complete | player enters `power_shutdown_trigger` | end: `SetLighting` (off → uses `LightsEnabled=false` default), one-shot `monster_reveal_cutscene.sound` |
| 6 | `unveil` | Introductions | `leaveroom` complete | `Timer 20 s` | start: **manual cutscene** at `introduction_campos`, 9 s, spawns a `Splitizen` that splits after 2 s |
| 7 | `turnpowerbackon` | Hey, who turned out the lights? | `leaveroom` complete | `InteractedWithType Generator` | end: `SetLighting true` |
| 8 | `blowuptheship` | Let's blow this joint! | `turnpowerbackon` complete | `InteractedWithType ShipConsole` | end: instantiate `selfdestructarms.vmdl` at `selfdestruct_pos` (`camPos`, 5 s, hide players) + `self_destruct_siren.sound` |
| 9 | `avoidmonster` | Do. Not. Die. | interact with `note_danger` | player enters `escapepod_outtro_trigger` | — |
| 10 | `escapepod` | Escape! | `blowuptheship` complete | player enters `escapepod_outtro_trigger` | start: `SetDoorLockState final_door`; end: instantiate `escapepod_complete.vmdl` at `escapepod_pos` (12 s, hide players) + `ShowCredits` |

Notes:
- Objectives 6 and 5 both start from `leaveroom` — parallel objectives are supported (lists, not a stack).
- `avoidmonster` has `InteractableName = note_danger` but no `Type` in its start condition → serialized `Type` defaults to `InteractWithEntity`.
- HUD shows all active objectives; new ones pop a 5 s "NEW OBJECTIVE" panel; `ObjectiveOverlay` draws a marker + distance over each end-condition target within 512 units.

### 2.2 Objective system semantics (old code)

- Server-only. `PendingObjectives` = every `ObjectiveResource` in the project; `ActiveObjectives` = started, not finished. Checked **every server tick** per pawn (`[Event.Tick.Server]`).
- Start conditions: `InteractWithEntity` (name match against `pawn.LastInteractedEntityName`), `PreviousObjectiveComplete` (resource path not in active *and* not in pending), `PlayerEnteredTrigger` (name match + trigger `TouchingEntities`).
- End conditions: `InteractWithEntity`, `InteractedWithEntity`, `InteractWithType`/`InteractedWithType` (C# type name), `PlayerEnteredTrigger`, `PlayerHasItem`, `Timer`.
- On transition: `ObjectivePanel.RpcAddObjective/RpcRemoveObjective` to everyone.
- Objective event types: `PlaySound`, `PlayCutscene` (existing entity), `PlayInstantiatedCutscene` (spawn model at named info target), `SetLighting`, `SetDoorLockState`, `PlayMonsterIntroductionCutscene`, `ShowCredits`.

### 2.4 Monster ("Splitizen → Monster")

| Rule | Value |
|---|---|
| States | `Dormant` (inside splitizen) → `Hiding` → `Stalking` → `Hunting` |
| Hiding | path 1024 u away from player; after **15 s** → Stalking |
| Stalking | speed 100, path to navmesh point 512–2048 u from player |
| Hunting | speed 200, bee-line to player position, kills within 70 u if player alive, not in cutscene, > 5 s since cutscene |
| Sight | 16 rays across 90° FOV, radius 4, 256 u from eye−16; hit pawn → Hunting; hit closed door the player has a key for → open it |
| Flashlight | if player lamp is on when seen → Hiding (exploitable on purpose) |
| Hearing | `sound level` decays 1/s; each sound event adds `volume` if `distance × (1−volume) < 128`; level > 1 → Hunting at last sound |
| Lost player | `IsFinished` path + 15 s since seen → Stalking |
| Stuck | average speed < 10 → random navmesh path, Stalking |
| Fell out of map | z < −32 → closest navmesh point, else respawn |
| Physics | hull ±16/z 0..72, gravity 300, friction 2, step 16 |
| Reveal | splitizen walks a random navmesh patrol; runs 1024 u from the helmet; `DoSplit()` after 2 s, 4 s of anim, then body ditched with impulse |
| Chase audio | `chase` loop while Hunting; on/off on state changes; volume API existed |

## 6. Port design, system by system

### 6.1 Scene and map

- Keep the old map as a **map asset**: `Assets/maps/horror_jam_map.vmap` + `Assets/maps/prefabs/*.vmap` (already copied; the game scene gets a `MapInstance` with `Map = horror_jam_map`).
- Modern scenes are `.scene`; the game scene should be `scenes/game.scene` holding `MapInstance`, `GameObjectSystem`s, lighting, and the prefab spawn point. `StartupScene` in `.sbproj` points there.
- Map needs `Enable NavMesh` and a navmesh built over the ship (monster + splitizen depend on it).
- **Custom map entities:** implement a `GvarMapInstance : MapInstance` overriding `OnCreateObject(GameObject, ObjectEntry kv)` and switch on `kv.TypeName`. Entity names and properties come from Hammer keyvalues, not `Library` lookups. `[HammerEntity]` classes can still be used for Hammer-side property UI, but routing everything through `OnCreateObject` keeps the old keyvalues (`ItemRequiredToOpen`, `IsViewable`, `ZoneName`, `NoteContents`, `ItemType`, `Amount`, `BatteryPower`) authoritative.
- Name resolution for objectives must be prefab-aware: match by exact name first, then by **suffix after the instance prefix**, and log a hard error on ambiguity. Better: add an `ObjectiveAnchorComponent` with a `[Property] string Id` set per instance/override, and have objectives reference that Id.

### 6.2 Player

Two options; recommend **(B)**:

**A. Built-in `PlayerController`** — fast, but the game's tuning (110/170 wish speed, 320 base, 500 ground accel, 0.25 stamina drain) is not exposed as properties in this build, so matching 1:1 requires reflection or accepting drift.

**B. Custom `MovementComponent` on a `PlayerController` with input disabled** — port `MovementController.cs` almost verbatim; modern replacement points:
- `Entity.Position` → `WorldPosition`, `Entity.Velocity` → `RigidBody.Velocity` (or `PlayerController.WishVelocity`).
- `MoveHelper.TryMoveWithStep` → `CharacterController` (`Accelerate`, `ApplyFriction`, `Punch`, `Trace`) or box sweeps via `Scene.Trace.Ray(...).Size(Hull)`.
- `Input.Pressed("Run")`, `Input.AnalogMove`, `Input.AnalogLook`, `Input.AnalogMove` all exist; keep `EyeAngles` clamped by `PlayerController` or by hand.
- Stamina stays a component with `[Sync] float Stamina`, identical constants.

Death/respawn: `HealthComponent` + ragdoll prefab (`playermodel.vmdl` + helmet + jumpsuit child renderers with `RigidBody`), respawn on `Input.Released("Jump")` when dead, teleport to `SpawnPoint` with +50 z.

Footsteps: `SkinnedModelRenderer.OnFootstepEvent` → `Scene.RunEvent<IMonsterNoise>( x => x.Noise( position, volume ) )`; surface via `Scene.Trace.Ray` (`tr.Surface.Sounds` equivalent is `Surface` — verify at port time).

### 6.3 Camera + effects

- `CameraComponent` on the player with `IsMainCamera`, `FieldOfView = Screen.CreateVerticalFieldOfView(90)` equivalent (`CameraComponent.FieldOfView` + `FovAxis`).
- First/third person = two `ICameraModifier` implementations with `CameraOrder`; keep the old third-person offset (back 64, right 16, radius 16 trace, exclude `camignore`).
- Bob/lean/FOV = one `ICameraModifier` porting `Pawn.CameraEffects.cs` math verbatim, writing to `CameraView` (`Position`, `Rotation`, `FieldOfView`).
- Breathing noise: Perlin → `Noise.Perlin` (still available in `Sandbox.Utility`).
- UI shake from bob: old code translated `Game.RootPanel`. Modern equivalent: a `PanelComponent` with `Panel.Style.Transform = new PanelTransform(...)`, or `Painter` transform.

### 6.4 Interaction

Design: player-side `InteractionComponent` (trace 100 u, ignore `trigger`, parent walk) + target-side `IPressable`:

```csharp
public interface IPressable
{
    bool CanPress( IPressable.Event e );
    bool Press( IPressable.Event e );         // hold semantics: return true to keep pressing
    void Blur( IPressable.Event e );
    string GetTooltip( IPressable.Event e );
}
```

`PlayerController` supplies `Hovered`/`Pressed`, `EnablePressing`, `ReachLength`, `UseButton`, and `IEvents.GetUsableComponent/StartPressing/StopPressing` if you want to reuse its using loop. The old hold-to-use progress maps to `Pressed` staying true + a `UseProgress` float on the target; UI reads it.

Keep the old gating rules: grounded + near-zero velocity, glow colours, `LastInteractedEntityName/TypeName` (used by objectives), locked-item snapping (camera override via `ICameraModifier`), `BlockMovement/BlockLook`.

### 6.5 Items, inventory, lamp

- `ItemType` → `enum` kept, but the display/model/material table becomes an `ItemDefinition : GameResource` (name, model, material group, model tint) so designers can edit without code. Inventory: `[Sync] NetDictionary<int,int>` (enum keys aren't directly supported — use `NetDictionary<int,int>` or `NetList<int>`).
- Helmet: `HelmetComponent` + child `SpotLight` at the `light` attachment; `BatteryPercentage`, power drain 0.05/tick, brightness 1.5×, tint `#B5B1FF`; `RenderColor` alpha = power %.
- Battery pickup: 3-phase `DelayedUseItem` → `TimedInteractionComponent` with phase list `(duration, action)`; drop old battery as a `Prop` with velocity `Rotation.Left * 100` and tint.
- Notes: `NoteComponent` + `WorldPanel`/screen panel; 1 s debounce; block movement.

### 6.6 Objectives

`ObjectiveResource : GameResource` with same fields, JSON on disk:

```json
{
  "ObjectiveName": "Locked In",
  "Description": "Find a key so you can leave the cryo room.",
  "ObjectiveStartConditions": [ { "Type": "PreviousObjectiveComplete", "ObjectiveName": "objectives/wakeup.objctv" } ],
  "ObjectiveEndConditions": [ { "Type": "PlayerHasItem", "ItemType": "KeycardLvl1" } ],
  "ObjectiveStartEvents": [],
  "ObjectiveEndEvents": []
}
```

Port rules:
- Conditions remain plain serializable structs with `[Property]`, `[ShowIf]` still exists, `ResourceType` still exists. Old `resource:"..."` refs become resource paths.
- `ObjectiveSystem : GameObjectSystem` ticks on host (`OnFixedUpdate`) and diffs `ActiveObjectives` to push UI updates; UI subscribes to a `Scene` event (`ObjectiveStarted`/`ObjectiveEnded`) instead of RPC statics.
- Events that referenced entities by name (`DoorName`, `InfoTarget`, `TargetEntityName`) must resolve through the prefab-aware name lookup or `ObjectiveAnchorComponent`.
- `ObjectiveTrigger` → GameObject with `BoxCollider { IsTrigger = true }` + `ObjectiveTriggerComponent`, named in Hammer. `func_nav_markup` stays a map-only helper.
- Keep the "one resource per objective, all resources pending at start" model; it is what makes the chain data-driven.

### 6.7 Cutscenes

Old model: swap the pawn's camera component, block movement/look, optional "press jump to continue", auto-end after duration, clean up spawned entities.

Modern model:
- `CutsceneCameraComponent : Component, ICameraModifier` with a target `GameObject`/attachment name; use `ModelRenderer.GetAttachmentObject(name)` for `camPos`, `lens_position`, `zonename`, `rhand_attach`.
- `CutsceneRunnerComponent` on the player: async method that sets `BlockMovement`, plays the camera, waits `Task.DelaySeconds`, restores camera, destroys temp objects. `Component.Task` auto-cancels on destroy.
- Manual cutscene (monster reveal): spawn `Splitizen` 1000 u in front at ground trace +2, face player, add red spot light (80° outer, 0.2 brightness), camera travels toward `LookAtPosition + Z*64` with roll `10 × t` — port `ManualCutsceneCamera.Update` math as-is.
- Anim triggers (`Open`, `split`, `right`, `left`, `grabitem`, `puthelmet`, etc.) keep working via the existing AG1 `.vanmgrph` files using `SkinnedModelRenderer.Set(...)` (`Parameters.Set(...)`); AG2 migration can wait until after gameplay is running.
- Optional: author fixed shots as Movie Maker sequences; code-driven is closer to 1:1 and avoids a second authoring surface.

### 6.8 Monster

- `MonsterComponent` holding the state enum + timers; `NavMeshAgent` for locomotion (`MoveTo`, `Stop`, `Velocity`), replacing `MoveHelper` + `NavPathBuilder`.
- Keep the sense logic exactly: 16×90° rays/256 u, sound-level accumulator, flashlight → Hiding, door-open assist, kill at 70 u, 15 s windows.
- `SplitizenComponent`: patrol via `NavMesh.GetRandomPoint` every 5–30 s, flee 1024 u from helmet, `DoSplit()` after 2 s; cosmetic monster + `SplitTop` as child renderers with `SkinnedModelRenderer` and body groups; `bangdoor` / `split` / `walkspeed` params drive the existing AG1 `.vanmgrph` graphs via `SkinnedModelRenderer.Set(...)`.
- Because `PlayerController` collides, the monster needs its own `RigidBody`/`CharacterController` with hull ±16/z 0..72 and gravity 300, mirroring old `TickMove`.
- Chase music hook: `AudioDirectorComponent.SetChase(bool)`.

### 6.9 Doors, power, lockers, cameras

- **Doors:** `Sandbox.Mapping.Door` gives pivot/slide/rotate/sounds/lock/link. Add `GvarDoorComponent` that carries `ItemRequiredToOpen`, `ObjectiveLocked`, `TimeSinceUsed` debounce (1 s) and implements `IPressable`; on press call `Door.Toggle()`. Keep `OpenAwayFromPlayer`. `final_door` lock toggle comes from the objective event.
- **Storage locker:** `ModelRenderer` + child door `ModelRenderer` rotated around `doorhinge`; interaction phases 0.6/0.5; spawn `LampBattery` when opened; optional `JanitorKey` requirement.
- **Player locker:** `LockedInteractionComponent`; camera override 100 u forward looking back.
- **Mounted camera:** `ModelRenderer` / `SkinnedModelRenderer` + custom tracking (dist < 300 && player below camera, slerp 10/s, driving the existing `mountedcamera.vanmgrph` `tracking`/`position`/`rotation` params via `SkinnedModelRenderer.Set(...)`).
- **Camera console:** `CameraComponent.RenderTarget` (verified member) rendering the selected `MountedCamera`'s view; feed the `console_screen` material parameter or `ModelRenderer.MaterialOverride` per selected camera; world `WorldPanel` for the zone name (`zoneName` attachment). Replace `ScenePortal` cleanly; no old API left.
- **Power/lighting:** `PowerSystem : GameObjectSystem` holding `LightsEnabled`, switching material groups on light models and `Enabled` on `PointLight`s, flicker `TimeUntil`, plus the light-cull behaviour (fade/disable lights out of view; distance < 256 or occluded).

### 6.10 HUD

- One `HudPanelComponent : PanelComponent` on a `ScreenPanel` GameObject, mirroring the old element list; prefer Razor for layout + `BuildHash()` for dynamic values, `Tick()` for per-frame bindings.
- The old `Graphics.CircleEx` ring → `Painter` (`Stroke`, `Arc`) or an SVG/`Image` with rotation; `Painter` is the supported path.
- `ObjectiveOverlay` markers: `Painter.Text` + icon font, or `Scene.Camera.ToScreen(position)`; clamp to screen margin 64 px, alpha over 128–512 u.
- World prompts: `WorldPanel` component + `PanelComponent` prefab; keep name + offset above bounds; billboard toward camera.
- Fonts: Chakra Petch + Gloria Hallelujah already present in `Assets/fonts`; register in stylesheet `@font-face`.

### 6.11 Audio

- All 52 `.sound` files are SoundEvents; `Sound.Play(sound, position)` returns `SoundHandle` (`Volume`, `Stop(fade)`, `Parent/FollowParent`).
- Ambience: loop a `SoundHandle`, restart when `!IsPlaying`; random one-shots every 50–80 s using `Sound.Play(sound, point)`; consider `SoundscapeTrigger` for the ship interior.
- Chase loop: single handle, `Stop(1f)` on state exit.
- Footstep/noise events: `Scene.RunEvent<IMonsterNoise>` is cheaper and host-authoritative compared to the old `[ConCmd.Server] ServerFootstep` hack.

### 6.12 Shader

`lcd_shader.shader` (LCD/monitor scanline shader for the console screen) is the only custom shader. It is currently **not compiling** ("Error opening shader … Feature combo not found", `CanRecompile=false`). Options:
1. Port to current `.shader` syntax (HEADER/MODES/COMMON still exist but `common/features.hlsl`, `IS_SM_50` targets are legacy); or
2. Rebuild in Shader Graph (material parameter `Texture` fed by `CameraComponent.RenderTarget`).

Until then, `monitor.vmat`/`monitoroff.vmat` fail and block `console_screen.vmdl`.

## 8. Risks, unknowns, decisions

**Risks**
1. **Animation graphs (downgraded — non-blocking).** All 10 `.vanmgrph` graphs (`console`, `cryochamber`, `mountedcamera`, `cryarms`, `cryarmsv2`, `escapepodarms`, `selfdestructarms`, `basic_splitizen`, `monster`, `playermodel`) still work via AG1 (`SkinnedModelRenderer.Set(...)`) and `CitizenAnimationHelper` still targets AG1. Caveats to watch: `splitizen_nosplit_blank.vmdl` references `models/citizen/citizen.vanmgrph` (verify it resolves or point it to `models/player/playermodel.vanmgrph`), `escapepod_complete.vmdl` has no `anim_graph_name` (uses `Sequence`), and AG1 action triggers vs AG2 are documented in `moving-from-ag1`. AG2 (`.ag`) rewrite is optional post-port cleanup.
2. **First-person body/IK fidelity.** Old code used per-bone props, `hold_L` parenting and `right_hand_ik` transforms. Modern equivalents exist (`CitizenAnimationHelper.IkLeftHand/IkRightHand`, `Transform` write), but hands-on feel needs iteration.
3. **Prefab instance renaming** breaks name-driven objectives/events (§6.1).
4. **Duplicate targetnames** (`power_shutdown_trigger` twice).
5. **`MaxPlayers 64` in the new `.sbproj`** — the game is single-player; running it as a 64-player networked game changes map loading and entity authority. Set `MaxPlayers=1`, `MapSelect=Hidden`, map list `horror_jam_map`.
6. **Flatgrass startup scene** — must be replaced by the game scene, or the game boots into flatgrass.
7. **Materials/shaders** are the biggest schedule item; do them before gameplay so models render while iterating.

**Decisions needed (defaults chosen)**
| Question | Default |
|---|---|
| Keep 1:1 custom movement vs `PlayerController` | Custom movement (1:1 numbers), `PlayerController` present but input disabled |
| Objectives as resources vs code graph | Resources (same model as 2023), converted to JSON |
| Camera console | `RenderTarget` on a material (no `ScenePortal`) |
| Cutscene authoring | Code-driven timed cameras (Movie Maker optional later) |
| Animation graphs | Keep AG1 `.vanmgrph` via `SkinnedModelRenderer.Set(...)` initially; migrate to AG2 `.ag` optionally after 1:1 parity |
| Asset source of truth | `Assets/` copies; `2023-repo/` stays read-only reference |
